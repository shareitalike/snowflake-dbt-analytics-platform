# Interview Notes: Snowflake Security & Architecture

## "Why are you creating `SECURE VIEWS` for your monitoring and metadata? Are you creating everything as a Secure View by default?"

**Answer:** No, we do not create *everything* as a `SECURE VIEW` by default because there is a performance penalty. We apply them strategically based on the data layer and the audience.

### 1. Why we use Secure Views for Monitoring & Metadata
In our architecture (e.g., `VW_TASK_EXECUTION_HISTORY`), we use `SECURE VIEW` because we are querying `INFORMATION_SCHEMA` and pipeline logs. 
If an ingestion pipeline fails because a JSON payload is malformed, the `ERROR_MESSAGE` generated by Snowflake might contain snippets of the raw JSON—which could contain PII (Personally Identifiable Information) like a customer's email or credit card token.

A standard view allows any user with `SELECT` access to run `GET_DDL()` to see the underlying code, or view the Query Profile to see the underlying execution plan (which exposes underlying data). A `SECURE VIEW` completely masks the underlying DDL, logic, and query plan from unauthorized users, ensuring PII doesn't leak into the hands of a junior analyst who is just checking task health.

### 2. When to use Standard Views vs Secure Views
* **Bronze/Silver Tier (Internal Engineering):** We use **Standard Views**. Data Engineers need to see the query plans and DDL to debug performance bottlenecks. Since `SECURE VIEW` prevents the Snowflake query optimizer from pushing down certain filters, we avoid them here to maximize performance.
* **Gold Tier / Data Sharing (External/Analytics):** We use **Secure Views**. If we are sharing data externally via Snowflake Data Sharing, or enforcing Row-Level Security (RLS) so a regional manager can only see their own store's data, we *must* use a Secure View. Otherwise, a clever user could bypass the RLS filter by inspecting the query plan.

**Summary:** Standard views for maximum performance in engineering tiers. Secure views for Metadata, Data Sharing, and Row Level Security.
